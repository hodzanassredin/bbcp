# История порта BlackBox на 64 бита — бриф (2026-08-18)

Реконструировано по git-логу bbcp, KB/, tasks/task-64bits.md, базе сессий
opencode (~/.local/share/opencode/opencode.db) и сессиям Kimi (~/.kimi/sessions).

## Папки (кто есть кто)

- `~/sources/bbcb2-2.0~a1.build332` — эталонный 32-битный BlackBox 2.0.
  Роль: хост для бутстрапа + источник эталона формата (подсистема Hr —
  прототип 64-битного компилятора, только для сверки, не для кода).
- `~/sources/bbcp` — ЦЕЛЕВОЙ репозиторий. Линуксовый порт BlackBox (GTK2),
  история с 2011 (А. Ширяев и др.). Сюда переносим 64 бита.
- `~/sources/bbcp64use` — собранный 64-битный «мир»: Sym/Code + симлинки
  на Mod из bbcp. Результат, запускается через bbcp/run-bb64.

## Хронология

### 0. Предыстория (2011–2012)
bbcp — 32-битный порт BlackBox на Linux/GTK2. Замёрз. Компилятор DevCP*
генерирует код i486, загрузчик — ELF-инжект, всё 32-битное.

### 1. Знакомство (15–20 июля 2026, opencode + DeepSeek)
Сессии deepseek-v4-pro/flash в bbcb2: изучение меню, компилятора Dev,
подсистемы Hr, сравнение DevCPL486 vs HrL, исходников ядра. Прямого
результата по порту не дали (пользователь: «дипсик что-то делал,
безуспешно»), но дали карту местности. Параллельно там же делались
расширения (JSON/Fjson) — к порту не относится.

### 2. Старт порта (21–23 июля)
- 21.07 — origin bbcp заменён на форк; bbcp становится целевой папкой.
- 21.07 — второй разработчик (Anton Shelin): 2 коммита «64 bit compiler»
  и «gui» — заготовка amd64-бэкенда (DevCPCamd64/CPLamd64/CPVamd64)
  и загрузчика bbrun64. Код рабочий, взят за основу.
- Решение: НЕ сохранять совместимость с 32-бит OCF. Новый нативный
  64-битный формат OCF v2 (эталон — Hr/Mod/Ocf.odc.txt).
- 21.07 — первая кровь: кодген клал ESP вместо RSP (нет REX.W) —
  починено в CPLamd64 (KB bbcb2 session-20260721).
- 22–23.07 — Fixup и резолюция импортов в bbrun64: «KERNEL OK»,
  91 модуль грузится, SysV FFI для [ccall], бут до LinLoader.

### 3. Бутстрап — как собирали (курица и яйцо)
Компилятор BB написан на Component Pascal → нужен работающий BB, чтобы
собрать BB. Схема:
1. 32-битный BlackBox (bbcb2) — хост.
2. В нём: правка `*/Mod/*.odc.txt` → OdcText.Import → .odc.
3. 32-битным DevCompiler собираем amd64-бэкенд (он 32-битный, но
   генерирует 64-битный код) → DevCompiler64 — кросс-компилятор.
4. DevCompiler64 компилирует все модули в 64-битные .ocf (OCF v2).
5. bbrun64 (C, Dev/Rsrc) — свой загрузчик: mmap модулей, Fixup,
   резолюция импортов, прыжок в Kernel64.
Позже цикл перенесён в bbcp (test64.sh/go64.sh), а 18.08 bbcp стал
самодостаточным: консольная BB64 сама гоняет OdcTextU.Batch
(round-trip .odc без bbcb2). bbcb2 нужен только как эталон Hr и
аварийный 32-битный bootstrap (dev0).

### 4. Подъём системы (24.07 – 09.08)
GC и единая куча CP Kernel; трап-машинерия на LONGINT (pc/sp/fp/val);
SysV ABI для GTK-колбэков (C→BB); GTK-хэндлы и dlsym-адреса LONGINT;
[ccall16]→[ccall]. Временный костыль MAP_32BIT для арены модулей/кучи
(пока в ядре жили 32-битные курсоры). 142 модуля, MAIN OK.

### 5. GUI (15.08)
Среда запускается: меню, окна, Log. Корни багов: MarkLocals align
(UAF в GC), двойной push FPU value-параметра (краши GC/финализаторов).

### 6. Чистка и ядро в 64 битах (17–18.08)
- Нативный Int64 в одном регистре (этапы 1–3): REX.W в CPLamd64,
  отключён DevCPH.UseReals (LONGINT раньше эмулировался ПАРОЙ 32-битных
  регистров через FPU!), удалён мёртвый код intrealtyp/lo-hi-хелперов.
- Куча >4 ГБ: MAP_32BIT снят, 4 латентных бага кодгена, GTK user_data
  LONGINT, ложный ASSERT в Kernel.Insert снят. TestBig: 80×64МБ=5ГБ,
  GC — OK.
- Зависание Tut-2: sliver-shadowing в Kernel.GetOldFreeBlock.
- INTO→JO (INTO невалиден в amd64, ovflchk через JNO+trap138).
- TLS: FS:[0] — это TLS glibc → осознанный fail-fast err 271 на
  guarded/interface процедуры вместо redesign.
- Аудит INTEGER-указателей (IntPtrAudit-64), UTF-8 унификация .odc.txt
  (OdcTextU), разбор всех TODO64, probes.sh 22/22 стабильно.

## Принятые решения (сводно)

1. Чистый 64-бит без обратной совместимости; 32-бит legacy выкидываем
   постепенно (32-битная пересборка Kernel/System уже невозможна —
   принято осознанно).
2. OCF v2 — нативный 64-битный формат модулей, эталон Hr.
3. Бутстрап: 32-бит хост → кросс-компилятор → мир bbcp64use →
   самодостаточный bbcp (BB64 конвертирует и компилирует сама).
4. MAP_32BIT — временный костыль ранней фазы; снят после починки
   кодгена (не оставлять костыли ради тестов).
5. GTK2/glib — системные 64-битные либы, SysV ABI (замена 32-битным).
6. Расширения (Aos, Crypto, Json, Mcp, _Http, Fjson, Async, Co_...)
   НЕ переносить в bbcp — отдельные репы, установка через Paket,
   порт каждого — отдельная работа.
7. Платформенные подсистемы (Win, Ole, Com, Ctl, Mdi, Fbsd, Nbsd, Obsd)
   ОСТАЮТСЯ: цель — Windows/Linux/FreeBSD. Их 64-бит порт — отдельный
   этап per-platform.
8. Процесс: правка .odc.txt (UTF-8) → sync-odc.sh → компиляция
   (go64.sh/build-dev64.sh) → probes.sh 22/22 → KB+tasks → коммит+пуш.
