# Баг forward reference / "multiply defined identifier" в 64-битном компиляторе (2026-08-18)

## Симптом

Компиляция внутри BB64 (GUI или консоль, т.е. 64-битным бинарём DevCompiler64)
модуля с расширением импортированной записи давала err 1 "multiply defined
identifier" на КАЖДОМ поле записи. Тот же исходник тем же исходником
компилятора, но 32-битным бинарём (dev0), собирался чисто. Всплыло на
Paket/Mod/Http.odc (Widget/Downloading).

## Корень

`DevCPT.InsertThisField` НЕ присваивала OUT-параметр `old` на успешных путях
(только в ветке дубля). Обёртка `InsertField` тут же проверяла
`IF old # NIL THEN err(1)` — чтение неинициализированной локальной переменной.
В 32-битном бинаре слот стека стабильно содержал NIL (остатки предыдущих
кадров), в 64-битном — мусор. Классика "работало по везению".

Фикс — одна строка в начале InsertThisField: `old := NIL;`.

Почему ловилось не на всех записях: содержимое мусорного слота зависит от
предыдущих вызовов; записи с базовым типом дёргают FindBaseField перед
InsertField и оставляли в том слоте не-NIL.

## Почему долго не всплывало

Все модули мира собираются 32-битным бинарём компилятора (dev0) — баг только
в 64-битном бинаре. 64-битным компилятором до этого момента собирали в
основном модули без расширения записей.

## Уроки / процесс

- **Отладочная печать в компиляторе**: CPP/CPT не импортируют StdLog; печатать
  через `DevCPM.LogWStr/LogW/LogWNum/LogWLn` (CPM уже тянет StdLog). Импорт
  StdLog в CPT напрямую тоже работает, но лишний импорт в сим-файле CPT
  заставляет пересобирать весь Dev — через CPM чище.
- **build-dev64.sh НЕ падает на ошибке модуля**: exit=0 при "== DevCPT ERROR"
  в середине лога. Проверять `grep -E 'err =|ERROR' лог` после каждого прогона.
  Симптом последствий: консоль виснет до timeout при загрузке компилятора
  (несогласованные osf/ocf — известная "консоль виснет, когда модуль не
  найден/бит").
- ORD(BOOLEAN) в нашем компиляторе не поддерживается (err 111) — печатать
  булевы через IF + строки.
- Минимальный репродюсер ≠ рабочий модуль: расширение Views.View требует
  реализации Restore (err 192) и в 32-битном компиляторе — сверять
  "одинаковость поведения" с 32-битным бинарём, а не "нет ошибок".

## Регрессионная проба

`probes.sh` теперь понимает `Compile:<Модуль>`: гоняет
`DevCompiler.CompileThis` в консоли BB64 и падает на "errors detected".
В ALL добавлена `Compile:ObxTestFwd2` (расширение Models.Message + forward
reference поля). Это первая проба, проверяющая сам 64-битный компилятор
изнутри мира.
