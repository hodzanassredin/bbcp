# Bootstrap: проблема курицы и яйца в BlackBox (32 и 64 бита)

Компилятор Component Pascal написан на Component Pascal → для сборки
BlackBox нужен работающий BlackBox. Цикл замыкается через доверенное
бинарное «семя», хранящееся в репо.

## 32-битный seed: dev0

`dev0Linux` (и `dev0.exe` на Windows) — двухслойный бинарь:
1. Статическая часть: `DevLinker1.LinkElfExe` линкует минимальный рантайм
   (Kernel, Utf, LinKernel, Files, LinEnv, LinFiles, LinPackedFiles,
   StdLoader, LinIntLoader) в standalone ELF.
2. Packed-часть: `DevPacker.PackThis` приклеивает ~50 модулей (Stores,
   Text, StdInterpreter, DevCommanders...) — при старте их распаковывает
   StdLoader. Модули компилятора DevCP* НЕ пакуются — грузятся из
   Dev/Code, чтобы правки компилятора не требовали перепаковки.
Рецепт пересборки: `tools64/repack-dev0.sh` (обе команды гоняются
внутри работающего BlackBox — run-dev0 / run-BlackBoxInterp).

## Цепочка семян (история)

- 1990-е: Oberon microsystems, BlackBox.exe (Windows, закрытый) — семя №0.
- ~2004: исходники открыты; дальше система self-hosted, бинарь —
  наследник исходного.
- 2011: А. Ширяев, порт на Linux — первый dev0Linux кросс-собран из
  Windows-версии. Хранится в репо, периодически перепаковывается.
- 2026: порт на amd64 — 32-битная система = семя, кросс-компилятор
  (DevCompiler64) + загрузчик bbrun64 (C) → 64-битный мир bbcp64use.
  Теперь BB64 собирает свой мир сама (OdcTextU, build-dev64),
  dev0 остаётся только драйвером полной пересборки (test64.sh).

## Практические следствия

- «С нуля безо всякого семени» собрать нельзя — нужен либо чужой
  работающий BlackBox, либо руками написанный второй компилятор CP.
- Sym-rot: бинарные .osf/.ocf в репо стареют относительно исходников;
  известные случаи — KB/Bootstrap32-symrot.md (DevCPM не пересобирается
  32-битным, его ocf рабочий — не трогаем).
- Trusting trust: независимого компилятора CP для перекрёстной
  верификации семени нет; Hr — производная тех же исходников, не счёт.
- Известный инцидент: правка экспортного интерфейса CPT ломает dev0
  (он грузит DevCP* по старым .osf) — лечится пересборкой чужим
  компилятором, см. KB/Bootstrap32-symrot.md.
